# Agent instructions

## Session notes

Keep a written record of the work so that a later session, or another agent, can continue without the conversation history.

- Record work in `docs/alpina/YYYY-MM-DD-session-notes.md`, one file per day. Create the day's file if it doesn't exist, and follow the format of the existing notes.
- For each piece of work, write what was done, why, which decisions were made, and the user's observations and corrections. Include anything not obvious from the code: rejected approaches, workarounds, limitations found, and what was or wasn't verified.
- Update the notes as work progresses, not only at the end. Add the entry after each completed step or decision, before moving on.
- When implementation state changes, also update `docs/alpina/migration.md` and the related topic doc in `docs/alpina/`.
- Omit credentials, key contents, hash salts, and one-time login URLs.
