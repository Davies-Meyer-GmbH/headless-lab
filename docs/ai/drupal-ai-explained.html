Drupal AI in our workflow

Drupal AI calls model APIs from inside Drupal and is billed per token through an API key. Our coding agents, Codex and Claude Code, run on their own subscriptions and work on Drupal from the outside. The map shows which side covers each stage of our process.

Your three questions

Which models can Drupal AI use?

Most of them.

Each provider has its own Drupal module: OpenAI, Anthropic, Gemini, Vertex, AWS Bedrock, Azure, Mistral, Hugging Face, and more. Local models run through Ollama or LiteLLM. Canvas AI needs a model that supports tool calling; its docs recommend a current GPT or Claude Sonnet-class model.

Can I use my Codex subscription in Drupal?

No.

Drupal AI providers sign in with an API key, and API use is billed per token, separately from ChatGPT plans. No Drupal provider supports "Sign in with ChatGPT". The subscription is for Codex itself, which works on Drupal from the outside through drush, scripts, or the MCP Server module. That is how the Alpina migration was built.

Is figma_canvas_ai a real Figma MCP?

No.

It's a proof of concept with no stable release, and no code runs in Drupal. It's a set of instructions for GitHub Copilot, which reads the design through Figma's own MCP server. That server, https://mcp.figma.com/mcp, works with Codex and Claude Code too, so the Figma step doesn't need Drupal AI.

Set up in headless-lab

  • Updated Drupal core from 11.4.9 to the 11.4.10 security release. Composer refused to add modules while core had open advisories.
  • Installed and enabled Drupal AI 1.5.1, AI Agents, API Explorer, Key, and the OpenAI and Anthropic providers.
  • Enabled Canvas AI, which adds six agents: orchestrator, page builder, template builder, component, title, and metadata.
  • Installed MCP Server 2.0 beta. drush mcp:server admin responds, but has no tools yet.
  • Connected both providers to key files in keys/. They are gitignored, so keys never reach the database or exported config.
  • You: paste an API key into keys/anthropic_api.key or keys/openai_api.key, then run setfacl -m u:www-data:r keys/<file> so Apache can read it.
  • You: choose the default model for each chat operation at /admin/config/ai/settings, and test it in the API Explorer.
  • You: open a page in Canvas and click the AI button to try the assistant.

Before relying on it

  • Results vary between runs. Canvas AI can pick a component ID or option value that doesn't exist, which breaks rendering.
  • Each Canvas AI request can send more than 30,000 tokens describing the available components. Disable unused components and keep descriptions short to lower the cost.
  • Component descriptions are how Canvas AI learns when to use each component. Write them for ours before editors start.
  • Since AI 1.3, the Canvas component agent may need "Disable hostname filtering" to create code components.
  • Unofficial gateways that turn a ChatGPT login into an API exist. Don't connect a shared company site to them.
