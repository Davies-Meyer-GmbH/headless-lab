Lesson 1: Agent or Drupal AI?

About 5 minutes. After it, you can decide for any AI task on next week's client project whether your coding agent or Drupal AI should do it.

Two ways to bring AI into the work

There are two routes. They differ in where the AI runs, what it changes, and who pays.

Agent route

  • Codex or Claude Code, outside Drupal.
  • Changes files, config, and scripts, which you review in Git.
  • Covered by the agent's subscription.

Drupal AI route

  • The AI module, inside Drupal, used through the admin UI.
  • Changes content that editors own: fields, pages, translations.
  • Billed per token through a provider's API key.

Drupal AI never uses your Codex or Claude subscription. Every request goes through a provider module, and the provider connects with an API key stored by the Key module. API use is billed separately from ChatGPT plans.

The one question that decides

Where does the result live?

If it belongs in the Git repo, such as a component, SCSS, a content type, or an import script, take the agent route. You get a diff to review, and the change can be run again on another environment.

If it belongs in the site's content, such as alt text, a translation, or a page an editor composes, take the Drupal AI route. The editor works in Drupal and reviews the result there.

Canvas AI can also generate components, but it saves them in Drupal, not in frontend/. That's why components stay on the agent route. See the Canvas AI docs.

AI Agents can create content types and fields too. Our re-runnable scripts stay on the agent route because they can be reviewed and repeated.
